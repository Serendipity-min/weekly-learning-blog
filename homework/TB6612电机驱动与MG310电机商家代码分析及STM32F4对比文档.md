## 1. 文档概述与硬件规格

### 1.1 硬件对象
* **主控芯片**：
  * **商家例程**：STM32F103C8T6（ARM Cortex-M3，主频 72MHz）
  * **我方平台**：STM32F407ZGT6（ARM Cortex-M4F，主频 168MHz，带硬件 FPU）
* **电机驱动板**：轮趣 **TB6612 双路电机驱动模块带稳压版**（型号 D153B / D153C）
  * 动力供电 VM：4.5V ~ 15V（推荐 7.4V 2S 动力锂电池）
  * 驱动能力：双路独立 H 桥，单路持续 1.2A，峰值 3.2A
  * 板载稳压：RT8289 开关降压输出 5V/5A，RT9013 LDO 输出 3.3V
  * 电池检测：板载 1/11 分压电阻网络引出至 ADC 端子
* **执行电机**：**MG310 直流减速电机**（霍尔编码器版）
  * 额定电压：7.4V，额定转速 400 RPM（空载 500 RPM），减速比 1:20，轴径 3mm（D型轴）
  * 额定工作电流 <= 0.5A，堵转电流 <= 2.0A
  * 霍尔编码器：13 ppr（电机转子每圈单相 13 脉冲），4 倍频后输出轴单圈计数为 $20 \times 13 \times 4 = 1040$ 个脉冲

### 2.2 电机驱动与控制逻辑详解

#### (1) TB6612 驱动芯片的硬件真值逻辑
TB6612FNG 采用典型 H 桥结构，根据 `IN1`、`IN2` 与 `PWM` 信号电平决定电机状态：

| IN1 (AIN1/BIN1) | IN2 (AIN2/BIN2) | PWM (PWMA/PWMB) | 电机运行状态 | 物理工作模式 |
| :---: | :---: | :---: | :---: | :--- |
| **0** | **1** | **PWM 脉冲** | **反转 (Reverse)** | 下桥臂导通，占空比决定转速 |
| **1** | **0** | **PWM 脉冲** | **正转 (Forward)** | 上桥臂导通，占空比决定转速 |
| **0** | **0** | X | **刹车停止 (Short Brake)** | 内部两个低端 MOS 导通，电机线圈短路自制动 |
| **1** | **1** | X | **刹车停止 (Short Brake)** | 内部两个高端 MOS 导通，电机线圈短路自制动 |
| X | X | **0** (或 STBY=0) | **自由滑行 (Stop / Standby)**| 所有 MOS 管关断，电机靠惯性自然减速 |

#### (2) 商家源码中的驱动实现 (`Set_PWM`)
在 `HAREWER\PWM\pwm.c` 中，商家编写了极具代表性的双向转速符号化驱动函数：

```c
void Set_PWM(int PWMA, int PWMB)
{
    // 电机 A 控制逻辑：根据正负号决定转向
    if(PWMA > 0) {
        GPIO_ResetBits(GPIOB, GPIO_Pin_14); // AIN1 = 0
        GPIO_SetBits(GPIOB, GPIO_Pin_15);   // AIN2 = 1 (正向旋转)
    } else {
        GPIO_SetBits(GPIOB, GPIO_Pin_14);   // AIN1 = 1
        GPIO_ResetBits(GPIOB, GPIO_Pin_15); // AIN2 = 0 (反向旋转)
        PWMA = -PWMA;                       // 占空比取绝对值
    }
    
    // 电机 B 控制逻辑：
    if(PWMB > 0) {
        GPIO_SetBits(GPIOB, GPIO_Pin_13);   // BIN1 = 1
        GPIO_ResetBits(GPIOB, GPIO_Pin_12); // BIN2 = 0 (正向旋转)
    } else {
        GPIO_ResetBits(GPIOB, GPIO_Pin_13); // BIN1 = 0
        GPIO_SetBits(GPIOB, GPIO_Pin_12);   // BIN2 = 1 (反向旋转)
        PWMB = -PWMB;                       // 占空比取绝对值
    }
    
    // 写入比较寄存器输出 PWM
    TIM_SetCompare4(TIM3, PWMA);  // 电机 A PWM -> TIM3_CH4 (PB1)
    TIM_SetCompare3(TIM3, PWMB);  // 电机 B PWM -> TIM3_CH3 (PB0)
}
```

#### (3) 系统调度与控制算法逻辑
* **开环模式（默认运行）**：
  在 `TIM1` 的 10ms 中断 (`TIM1_UP_IRQHandler`) 中：
  ```c
  encoder_A = Read_Encoder(4);  // 读取电机 A 增量 (TIM4)
  encoder_B = Read_Encoder(2);  // 读取电机 B 增量 (TIM2)
  Velocity_PWMA = 3000;         // 固定给定 PWM 比较值
  Velocity_PWMB = 3000;
  Set_PWM(Velocity_PWMA, Velocity_PWMB);
  ```
  每隔 100 次中断（即 $10\text{ms} \times 100 = 1\text{s}$），通过 `USART1` 打印当前电压、编码器计数值和实际输出 PWM。
* **闭环模式（位置式/增量式 PI 控制）**：
  商家提供了增量式速度 PI 算法 (`Velocity_A` / `Velocity_B`)：
  $$\text{Bias} = \text{TargetVelocity} - \text{CurrentVelocity}$$
  $$\text{ControlVelocity} += K_p \times (\text{Bias} - \text{LastBias}) + K_i \times \text{Bias}$$
  限幅在 $[-7200, 7200]$ 范围内，实现转速动态自适应稳定。

### 2.3 PWM 频率与初始占空比严密推导

#### (1) 定时器时钟源与频率计算
1. **时钟树结构**：STM32F103 的系统主频为 $72\text{ MHz}$。TIM3 挂载在 **APB1 总线**（PCLK1 最大为 $36\text{ MHz}$）。
2. **定时器内部倍频规则**：STM32 规定，当 APB1 预分频系数为 1 时，定时器时钟等于 PCLK1；当 APB1 分频系数大于 1（此处为 2 分频，72MHz/2 = 36MHz）时，定时器的输入时钟自动倍频为 PCLK1 的 2 倍，即：
   $$f_{\text{TIM3CLK}} = 36\text{ MHz} \times 2 = 72\text{ MHz}$$
3. **寄存器配置值**：
   在 `PWM_Int(7199, 0)` 函数调用中：
   * 预分频值 `Prescaler (PSC)` = 0
   * 自动重装载值 `Period (ARR)` = 7199
4. **PWM 输出频率计算公式**：
   $$f_{\text{PWM}} = \frac{f_{\text{TIM3CLK}}}{(\text{PSC} + 1) \times (\text{ARR} + 1)} = \frac{72\,000\,000}{(0 + 1) \times (7199 + 1)} = \frac{72\,000\,000}{7200} = 10\,000\text{ Hz} = 10\text{ kHz}$$
   **结论：商家的 PWM 调制频率为 10 kHz。**（10kHz 处于人耳可闻噪声敏感度较低频段，同时开关损耗在 TB6612 的 100kHz 限额内，属于直流电机的黄金驱动频率）。

#### (2) 初始占空比推导
* **硬件初始化时刻（`PWM_Int` 刚刚执行完毕）**：
  在初始化代码中设置：
  ```c
  TIM_OCInitStructure.TIM_Pulse = 0; // 比较捕获值 CCR 初始写入 0
  ```
  此时定时器输出占空比为：
  $$\text{Duty Cycle}_{\text{Init}} = \frac{0}{7199 + 1} = 0\%$$
* **程序开始运行时刻（进入 `TIM1` 第一次 10ms 中断）**：
  例程直接对速度变量赋值：
  ```c
  Velocity_PWMA = 3000;
  Velocity_PWMB = 3000;
  Set_PWM(Velocity_PWMA, Velocity_PWMB);
  ```
  此时比较寄存器写入 $CCR = 3000$，有效占空比计算为：
  $$\text{Duty Cycle}_{\text{Run}} = \frac{CCR4}{ARR + 1} = \frac{3000}{7200} = \frac{5}{12} \approx 41.67\%$$

## 3. 我方 STM32F4 工程实现解析（PWM_LED）

我方在 `C:\Users\Serendipity\OneDrive\桌面\0907\PWM_LED` 工程中实现了一套基于按键交互与 LED 状态指示的电机控制架构。

### 3.1 架构与引脚分配
* **主控平台**：STM32F407ZGT6
* **电机引脚映射**：
  * **PWM 调速输出**：
    * `PB0` -> 复用映射至 **TIM3_CH3**
    * `PB1` -> 复用映射至 **TIM3_CH4**
  * **方向控制输出**：
    * `PE0` -> 通用推挽输出（对应 TB6612 AIN1/BIN1）
    * `PE1` -> 通用推挽输出（对应 TB6612 AIN2/BIN2）
* **人机交互接口**：
  * `KEY_UP (PA0)`：步进加速键（+10%）
  * `KEY0 (PE4)`：步进减速键（-10%，降至 0% 自动刹车）
  * `KEY1 (PE3)`：正转启动 / 刹车停止切换
  * `KEY2 (PE2)`：反转启动 / 刹车停止切换
  * `LED0 (PF9)`：运行指示灯（点亮表示运行，熄灭表示停转）
  * `LED1 (PF10)`：反转指示灯（点亮表示当前处于反转状态）

### 3.2 定时器时钟与 10kHz PWM 配置
1. **STM32F407 时钟树总线特性**：
   * 系统内核主频：$f_{\text{SYSCLK}} = 168\text{ MHz}$
   * APB1 外设总线预分频为 4，时钟频率 $f_{\text{PCLK1}} = 168 / 4 = 42\text{ MHz}$。
   * 根据 STM32F4xx 参考手册，当 APB 分频系数大于 1 时，定时器内部输入时钟为 PCLK 的 2 倍：
     $$f_{\text{TIM3CLK}} = 42\text{ MHz} \times 2 = 84\text{ MHz}$$
2. **PWM 时基参数与计算**：
   在我方 `HARDWARE\pwm.c` 的 `Motor_Init()` 中：
   * 预分频器：`TIM_Prescaler = 0`
   * 自动重装载值：`TIM_Period = 8400 - 1 = 8399`
   * PWM 频率：
     $$f_{\text{PWM}} = \frac{84\,000\,000}{(0 + 1) \times (8399 + 1)} = \frac{84\,000\,000}{8400} = 10\,000\text{ Hz} = 10\text{ kHz}$$
3. **占空比换算与步进控制**：
   我方采用规整的百分比映射算法：
   ```c
   compare_val = (uint32_t)speed_percent * 84;
   TIM_SetCompare3(TIM3, compare_val);
   TIM_SetCompare4(TIM3, compare_val);
   ```
   当 `speed_percent = 100` 时，写入 8400（满占空比 100%）；每步进 10%，计数值增减 840。

### 3.3 按键交互与控制逻辑
我方定义了清晰的状态枚举：
```c
typedef enum {
    MOTOR_DIR_STOP    = 0,  /* 刹车制动：PE0=0, PE1=0, PWM=0 */
    MOTOR_DIR_FORWARD = 1,  /* 正向转动：PE0=1, PE1=0, 输出PWM */
    MOTOR_DIR_REVERSE = 2   /* 反向转动：PE0=0, PE1=1, 输出PWM */
} MotorDir_t;
```
当进入 `MOTOR_DIR_STOP` 时，硬件强制 `PE0=0, PE1=0` 且将 `TIM_SetCompare` 置零，TB6612 立即进入死区短路刹车，相比自然滑行停转更迅速安全。

## 4. 商家 F1 代码 vs 我方 F4 代码 核心差异对比

### 4.1 引脚分配与板载硬件冲突分析（极重要）

这是**移植过程中最致命的隐患**。商家代码是针对只有 48 脚的 STM32F103C8T6 最小系统板编写的，如果直接把商家引脚照搬到当前 STM32F407ZGT6 开发板上，会发生严重硬件冲突：

| 引脚编号 | 商家 F1 例程用途 | 我方开发板板载集成外设 | 冲突后果（若直接照搬商家代码） | 我方 F4 工程的处理与优化 |
| :--- | :--- | :--- | :--- | :--- |
| **PB12** | 电机 B 方向 BIN2 | **WM8978 (I2S_LRCK) / CAN2_RX** | 音频总线信号被电机脉冲干扰，CAN 通信异常 | 隔离避让 |
| **PB13** | 电机 B 方向 BIN1 | **WM8978 (I2S_SCLK) / CAN2_TX** | 同上 | 隔离避让 |
| **PB14** | 电机 A 方向 AIN1 | **W25Q128 外部 SPI Flash 片选 (`F_CS`)** | **灾难性冲突**：电平翻转导致 Flash 误使能，程序读写 Flash 崩溃 | **果断避开 PB14**，改用干净的 **PE0** |
| **PB15** | 电机 A 方向 AIN2 | **TFT LCD 液晶屏背光使能 (`LCD_BL`)** | **严重冲突**：电机运转会导致液晶屏背光剧烈闪烁或黑屏 | **果断避开 PB15**，改用干净的 **PE1** |
| **PA0** | 电机 B 编码器 E2A | **板载按键 KEY_UP（硬件带 10k 下拉）** | 编码器方波被板载按键下拉电容滤波畸变，按键误触发 | 我方工程将 PA0 用作按键输入；后续编码器规划至 **PC6** |
| **PB0** | 电机 B 速度 PWMB | **TIM3_CH3 (PWM)** | 无冲突（排针引出） | 保留作为 TIM3_CH3 输出 |
| **PB1** | 电机 A 速度 PWMA | **TIM3_CH4 (PWM)** | 无冲突（排针引出） | 保留作为 TIM3_CH4 输出 |

> **结论与评价**：
> 我方 F4 代码放弃商家的 `PB12~PB15`，改用 `PE0` 和 `PE1` 作为电机方向引脚，是**深度结合开发板原理图后非常明智的避坑设计**，彻底规避了板载 SPI Flash 和 LCD 背光的硬件冲突！

### 4.2 时钟树总线与定时器参数对比

| 比较维度 | 商家 STM32F1 例程 | 我方 STM32F4 工程 | 差异本质与技术原由 |
| :--- | :--- | :--- | :--- |
| **芯片内核** | Cortex-M3 @ 72 MHz | Cortex-M4F @ 168 MHz | F4 计算性能大幅提升，具备硬件浮点单元 FPU |
| **TIM3 挂载总线** | APB1 (PCLK1 = 36MHz) | APB1 (PCLK1 = 42MHz) | F4 的总线带宽和分频机制不同 |
| **TIM3 时钟源频率** | $36\text{ MHz} \times 2 = \mathbf{72\text{ MHz}}$ | $42\text{ MHz} \times 2 = \mathbf{84\text{ MHz}}$ | F4 定时器时钟基准高出 12MHz |
| **PWM 调制频率** | **10 kHz** | **10 kHz** | 两者均达到 10kHz 理想电机工作频率 |
| **预分频器 (PSC)** | `PSC = 0` | `PSC = 0` | 均不分频，保证最高的时间精度 |
| **自动重装载值 (ARR)**| `ARR = 7199`（满量程 7200） | `ARR = 8399`（满量程 8400） | **因输入时钟差异，F4 必须增加计数值以维持 10kHz** |
| **占空比步进精度** | 1 / 7200 ≈ 0.0139% | 1 / 8400 ≈ 0.0119% | F4 具有更细腻的 PWM 调速分辨率 |
| **速度赋值方式** | 裸数值（如 3000） | 百分比乘系数：`percent * 84` | 我方接口封装更人性化，0~100 范围一目了然 |

### 4.3 GPIO 驱动架构与固件库配置差异（F1 vs F4）

在固件库编程层面上，STM32F1 与 STM32F4 存在代际差异：

#### 1. GPIO 时钟使能总线不同
* **F1 代码**：
  ```c
  RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE); // F1 的 GPIO 位于 APB2
  ```
* **F4 代码**：
  ```c
  RCC_AHB1PeriphClockCmd(RCC_AHB1Periph_GPIOB | RCC_AHB1Periph_GPIOE, ENABLE); // F4 的 GPIO 挂载在高速 AHB1 总线
  ```

#### 2. 引脚复用映射机制截然不同
* **F1 机制**：引脚复用通过 `GPIO_Mode_AF_PP` 即可将外设信号直通引脚，若需重映射则使用全局的 `AFIO` (`GPIO_PinRemapConfig`)。
* **F4 机制**：引入了内部复用器（AF0~AF15）。引脚模式必须设为通用复用 `GPIO_Mode_AF`，并且**必须显式调用引脚源映射函数**：
  ```c
  GPIO_PinAFConfig(GPIOB, GPIO_PinSource0, GPIO_AF_TIM3); // 显式绑定 PB0 到 TIM3
  GPIO_PinAFConfig(GPIOB, GPIO_PinSource1, GPIO_AF_TIM3); // 显式绑定 PB1 到 TIM3
  ```

#### 3. GPIO 结构体字段差异
* **F1**：`GPIO_Mode` 复合了输入输出和上下拉（如 `GPIO_Mode_Out_PP`, `GPIO_Mode_IN_FLOATING`）。
* **F4**：解耦为四个独立属性：
  * `GPIO_Mode`：`Mode_IN` / `Mode_OUT` / `Mode_AF` / `Mode_AN`
  * `GPIO_OType`：`OType_PP`（推挽） / `OType_OD`（开漏）
  * `GPIO_PuPd`：`PuPd_NOPULL` / `PuPd_UP` / `PuPd_DOWN`
  * `GPIO_Speed`：`Speed_2MHz` / `25MHz` / `50MHz` / `100MHz`

## 5. STM32F407 接入 MG310 + TB6612 的工程落地与安全指南

为了在我方 STM32F407ZGT6 开发板上完整实现双路 MG310 电机的高性能驱动与闭环控制，推荐以下工程方案：

### 5.1 完整双路接线规划推荐表（避让所有板载外设）

根据开发板两侧的双排 60-Pin 排针（P8 / P9），推荐接线分配如下：

| TB6612 驱动板端子 | 推荐 STM32F407 引脚 | 物理排针位置 | 引脚复用功能 | 功能规划说明 |
| :--- | :--- | :--- | :--- | :--- |
| **5V (电源输出)** | **+5V** | P9 Pin 57 / 58 | 系统电源输入 | 驱动板稳压 5V 直接给开发板供电 |
| **GND (公共地)** | **GND** | P9 Pin 55 / 56 | 系统电源地 | **两板严格共地（红线安全原则）** |
| **STBY (使能端)** | **+3.3V** 或 **PD3**| P9 Pin 59 / P8 Pin 22 | 逻辑高电平 / GPIO | 常开使能（接3.3V）或软件低功耗控制 |

### 5.2 核心电气安全红线（防止烧芯片与单片机）
1. **必须严格共地**：
   外部 7.4V 锂电池负极、TB6612 驱动板 GND、STM32 开发板 GND 必须使用粗杜邦线牢固连接。若不共地，控制逻辑电平浮空，电机将剧烈抖动失控甚至击穿端口。
2. **严禁 GPIO 直驱电机**：
   STM32F4 的 GPIO 引脚驱动能力仅 25mA，而 MG310 电机堵转电流高达 2.0A。严禁将单片机引脚直接碰触电机动力线。
3. **严禁带电插拔电机动力线**：
   MG310 电机内部绕组电感为 $30.7\text{ mH}$。带电拔掉排线瞬间产生的反向自感电动势高达数十伏，会瞬间击穿 TB6612 内部 MOS 管。
4. **编码器供电严禁接错或超压**：
   霍尔编码器只能接入驱动板稳压输出的 5V（或 3.3V）。如果误将 7.4V 锂电直接接上编码器供电脚，会瞬间烧毁霍尔元器件，高电压串入单片机定时器引脚更会直接烧毁 STM32 芯片。
5. **PID 极性与防“飞车”处理**：
   当后续引入编码器闭环后，若电机出现全速暴冲（飞车），说明编码器极性与驱动极性相反导致了正反馈。此时只需在中断读取函数中对计数值加负号即可恢复负反馈稳定：
   ```c
   encoder_speed = -Read_Encoder(); // 极性反转消除正反馈
   ```
